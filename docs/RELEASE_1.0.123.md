# Potato Launcher v1.0.123 — runaway clients held at 60, safer placement test

- **Runaway clients are held at the target.** A client with no in-game frame limit (Frame Rate: None) that is render-cut or covered draws no frames, so the NVIDIA cap cannot pace it: on a 9950X3D such followers ran at 83-185 FPS, the CPU hit 100% and other clients dropped to 5-27 FPS. Potato now holds any such client at the target FPS with the same CPU cap it uses for minimized windows. It never holds the client you are playing or your main, and lets go as soon as the client has its in-game limit. The Cap column shows "held by Potato" and the Optimizer explains how to set the in-game limit, which is cheaper and steadier.
- **Placement test can no longer store nonsense.** With the CPU saturated, Potato's own timer stalled and one measurement covered almost no time ("clients 649%", "main 1155 FPS"). Measurements are now timed from their own start, a stalled or impossible run is stopped with an explanation, and the test refuses to start while clients run without their in-game limit. Earlier results are discarded.
- Fixed: turning off the TextInputHost reset also turned off the CPU cap for minimized clients.
- Measured on a 9800X3D main (6 minutes): the game's own 60 limit used 6.26% CPU at 57.9 FPS; Frame Rate None with the NVIDIA cap used 7.07% at 60.0 (17.3 vs 18.9 ms CPU per frame). Potato keeps setting the in-game limit at launch.
