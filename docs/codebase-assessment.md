# Codebase Assessment

## Current Strengths

- The app has a clear product goal, portable install model, and release workflow.
- Core user data is already separated from XIVLauncher passwords and game memory.
- Recent tests cover migration cleanup, layout clamps, helper text, and custom slider behavior.

## Weak Areas

- `Program.cs` is a monolith. It contains app models, settings migration, launch orchestration, Lodestone scraping, updater logic, theme rendering, custom controls, and the main form. This makes visual regressions and launch regressions more likely because unrelated changes share one file.
- UI updates are still mostly manual WinForms `Bounds` assignments. That is workable, but every resize/theme change must be carefully batched because small invalidation mistakes can cause flicker or stale paint.
- Launch polling updates status text frequently. Duplicate text should be throttled so waiting loops do not trigger unnecessary repaints.
- Settings cleanup should keep stripping old or malformed persisted values. Empty account-icon profiles and whitespace-padded keys can be generated by old builds or partial profile-link flows.
- Release packaging was too easy to run after launching from `publish`, which can leave generated `settings.json`, `accountList.json`, or `band.json` beside the executable.

## Improvement Direction

- Split `Program.cs` gradually by responsibility instead of doing a risky big-bang rewrite:
  - `Models.cs` for data records and transfer objects.
  - `SettingsMigration.cs` for settings and portable state cleanup.
  - `LauncherLayoutMetrics.cs` for layout math.
  - `LaunchServices.cs` for BAT/shared launcher command building and readiness polling.
  - `ThemeControls.cs` for custom panels, sliders, tooltips, and roster controls.
- Keep UI smooth by centralizing status/loading text updates, avoiding synchronous `Refresh()`, and invalidating only the smallest useful area during animation.
- Keep migration tests growing whenever a stored field moves, gets renamed, or becomes obsolete.
- Use `scripts/package-release.ps1` for releases so generated user data is removed and the zip is verified before upload.
